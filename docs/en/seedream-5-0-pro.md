## Choose one information job

An infographic should answer one customer question, not compress an entire product page into one frame.

| Information job | Customer question | Useful visual structure |
|---|---|---|
| Feature callout | What is the visible feature? | One product view, one highlighted area, one concise explanation |
| Specification comparison | Which approved option fits my need? | Aligned columns, repeated labels, equal visual weight |
| Process diagram | How does the product or service work? | Ordered steps, directional flow, consistent icons |
| Detail-page block | Why does this product fact matter? | Claim, visual proof, short supporting explanation |
| Precise correction | What single part of an approved image must change? | One local edit with all unrelated areas kept stable |

Use separate graphics for unrelated questions. A focused structure makes factual review and later correction easier.

## Build a claim-and-layout sheet

Prepare the following before creating the image:

1. **Customer question:** the one decision the graphic should help a shopper make;
2. **Approved claim:** exact wording from a reviewed product, legal, or marketing source;
3. **Evidence:** the specification sheet, packaging file, product photography, or approved internal record that supports the claim;
4. **Visual proof:** the product detail, comparison, diagram, or icon that explains the claim;
5. **Copy hierarchy:** headline, supporting line, labels, units, and required disclaimer;
6. **Delivery rules:** aspect ratio, copy-safe area, brand colors, asset rights, and destination requirements.

Keep claims and creative styling separate. Color, spacing, and visual mood can change; approved wording, numbers, units, product structure, and brand details should not.

## Five-step Seedream 5.0 Pro workflow

### 1. Open the official model page

Start from the [Seedream 5.0 Pro page on Flux Art](https://flux-art.ai/en/models/seedream-5-0-pro). Confirm whether the task is a new infographic or one precise correction to an approved image.

### 2. Sketch the information hierarchy

Arrange the headline, product, visual proof, labels, and supporting copy as simple blocks. Decide what the customer must notice first, second, and third. Remove any element that does not support that reading order.

### 3. Write observable layout instructions

Describe the product facts, grid, alignment, spacing, color, typography role, copy-safe area, and prohibited additions. Use exact approved copy when text belongs in the image, but plan to verify it character by character after generation.

### 4. Correct one local problem at a time

For a precise edit, name the selected area, the requested change, and the parts that must remain unchanged. Flux Art supports inpainting-style local edits through its image-editing entry point. If the change affects unrelated areas, return to the approved source image and narrow the edit brief.

### 5. Run an information release check

Compare every claim, number, unit, label, logo, package detail, and disclaimer with the approved sources. If exact typography is business-critical, complete final typesetting in the team's design tool after the visual direction is approved. Check asset rights, AI-content labeling, and the destination platform's current rules with the [compliance checklist](../06-compliance.md).

## Two prompts to adapt

### Two-size bottle comparison infographic

```text
Create a clean ecommerce comparison infographic for two stainless-steel insulated bottles from the same approved product line: one 500 ml bottle and one 750 ml bottle. Show both bottles at equal visual scale on a warm-white background. Keep the cylindrical body shape, matte navy finish, silver cap structure, front logo position, and material appearance consistent. Use two aligned columns with the exact headings “500 ml” and “750 ml,” one simple bottle icon above each heading, and a quiet footer area for final typesetting. Use dark navy and light gray for the information system. Do not add performance claims, prices, badges, decorative props, extra bottle sizes, or unapproved text.
```

Verify both capacity labels and all product details against the approved specification sheet before release.

### Precise package-color correction

```text
Edit the supplied ecommerce product image. Change only the pale-blue side panel on the carton to the approved dark-green color. Keep the carton dimensions, front artwork, logo, product name, barcode area, paper texture, camera angle, crop, lighting, background, contact shadow, and every other color unchanged. Do not add text, graphics, reflections, props, or another package.
```

Compare the corrected area with the approved packaging file and the unchanged areas with the original image.

## Review and correction table

| Problem | Check first | Next correction |
|---|---|---|
| Claim is unsupported | Claim-and-layout sheet and evidence source | Remove or replace the claim before visual refinement |
| Number or unit is wrong | Specification sheet and exact approved copy | Correct the text, then verify every character again |
| Reading order is unclear | Headline size, block order, contrast, spacing | Reduce competing elements and restore one primary hierarchy |
| Product detail changed | Shape, material, logo, label, package structure | Restate the fixed product facts and simplify the composition |
| Local edit changed other areas | Selected region and edit brief | Return to the approved source and narrow the requested change |
| Graphic looks finished but cannot ship | Disclaimer, asset rights, labeling, destination rules | Complete the release check before export |
